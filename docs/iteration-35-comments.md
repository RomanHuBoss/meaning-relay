# Итерация 35 — русскоязычные комментарии исходного кода

## Правило

Каждый исполняемый модуль проекта должен содержать пояснение на русском языке.
Для сложной логики комментарии объясняют причину решения: порядок блокировок,
идемпотентность, защиту токенов, сокрытие данных, сроки хранения и обработку
ошибок. Комментарии не пересказывают очевидную строку кода.

Технические имена, названия протоколов, переменных окружения и библиотек
сохраняются в исходном виде, когда их нельзя заменить без потери точности.
Служебные директивы линтера вроде `/* global ... */` не считаются
пояснительными комментариями и исключены из языкового правила.

## Проверка

`tests/unit/russian-comments-contract.test.ts` рекурсивно перечисляет исходные
модули приложения, компоненты, библиотеку, общие пакеты, сценарии, миграции и
тесты. Затем она проверяет два свойства:

1. в каждом модуле есть комментарий с кириллическим текстом;
2. среди пояснительных комментариев нет строк без кириллицы.

Изменение схемы, маршрута, сценария обслуживания или теста без пояснения теперь
ломает общий модульный прогон и требует добавить осмысленный комментарий вместе
с кодом.
