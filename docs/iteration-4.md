# Итерация 4 — административный контур

Эта итерация добавляет серверную основу панели администратора поверх уже
работающего relay core и публичного moderation API.

## Что сделано

- Добавлен `POST /api/v1/admin/login`.
  - Принимает только закрытую схему `{admin_key}`.
  - Проверяет CSRF и ограничивает попытки по хешу IP: 5 попыток в 15-минутном
    UTC-бакете.
  - Сравнивает `ADMIN_KEY` через `timingSafeEqual`.
  - Выдаёт непрозрачный `HttpOnly` cookie `admin_sid` со сроком 8 часов.
- Добавлен `POST /api/v1/admin/logout`.
  - Отзывает серверную сессию и удаляет cookie.
  - Повторный logout без действующей сессии остаётся идемпотентным.
- Добавлен `GET /api/v1/admin/dashboard`.
  - Возвращает публичные relay-агрегаты, количество открытых жалоб и счётчик
    ошибок за последние 24 часа.
  - In-memory режим считает открытые жалобы из текущего процесса; PostgreSQL
    режим читает агрегаты из таблиц `reports` и `events`.
- Добавлены административные read/mutation routes для themes, chains и reports:
  создание и редактирование seed-тем, batch-создание цепочек с проверкой
  активной темы и cap 50 на язык, просмотр цепочки, pause/resume/archive,
  список жалоб и атомарные решения `dismiss`, `hide-message` и
  `archive-chain`.
- Для list endpoints добавлены закрытые фильтры, лимиты 1..50 и подписанные
  cursor-значения; все admin mutations требуют действующую `admin_sid` и
  double-submit CSRF.
- Добавлена публичная карта `GET /api/v1/map?period=24h|all` с агрегатами
  `country_code + count`, k-анонимностью для малых групп (`OTHER`) и отдельным
  bucket `UNKNOWN` для submit без страны. Идентификаторы участников и сообщений
  в ответ не попадают.
- Добавлен общий helper административной сессии с PostgreSQL и in-memory
  fallback. В storage попадает только SHA-256 хеш токена.
- Уточнены коды ошибок и rate-limit окна: `ADMIN_LOGIN=5/15m`,
  `REPORT=5/1h`, остальные пользовательские операции сохраняют окно 10 минут.

## Проверка

Выполнены unit-тесты, TypeScript-проверка, lint и production build. Live
PostgreSQL race-тесты требуют доступной базы и запускаются отдельно после
применения `migrations/001_initial.sql`.
