# Итерация 37 — PostgreSQL acceptance harness

Интеграционный набор расширен сценариями, которые выполняются только при
одновременном задании `DATABASE_URL` и `POSTGRES_ACCEPTANCE_MUTATE=1`.

## Добавленные проверки

- отдельные цепочки для изменяющих тестов и гарантированная очистка после
  прогона;
- завершение цепочки ровно на двенадцатом сообщении;
- отсутствие тринадцатого claim после завершения;
- сохранение ровно двенадцати сообщений и claims;
- создание жалобы на завершённое сообщение;
- архивирование цепочки через административный переход;
- перевод жалобы в `CHAIN_ARCHIVED` и заполнение `resolved_at`;
- сохранение прежних проверок двадцати повторных submit с одним ключом и
  отклонения отложенной внешней связи при фиксации транзакции.

Без PostgreSQL изменяющая группа остаётся пропущенной, а read-only группа также
не запускается: это честно показывает отсутствие внешней базы и не превращает
статический контракт в ложное подтверждение интеграции.

Запуск:

```text
DATABASE_URL=... POSTGRES_ACCEPTANCE=1 POSTGRES_ACCEPTANCE_MUTATE=1 npm run test:postgres
```

Перед запуском на общей базе следует использовать отдельную тестовую схему или
восстановимый стенд: изменяющая группа создаёт и удаляет тестовые темы, цепочки,
claims, сообщения и жалобы.
