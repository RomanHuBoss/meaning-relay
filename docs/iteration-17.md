# Итерация 17 — bounded maintenance CLI

Ручной `npm run maintenance` теперь ограничивает время ожидания HTTP endpoint
через `MAINTENANCE_TIMEOUT_MS` (по умолчанию 15 секунд). При сетевой ошибке,
таймауте или недопустимом значении timeout команда печатает диагностическое
сообщение и завершается с ненулевым exit code; секрет в вывод не попадает.

Добавлен unit smoke для трёх эксплуатационных исходов: отсутствие
`CRON_SECRET`, успешный POST с Bearer-заголовком и ограниченный таймаут
недоступного endpoint. Это делает ручной запуск и cron-wrapper пригодными для
контролируемого health/maintenance job даже до подключения PostgreSQL.
